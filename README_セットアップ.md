# 宇佐美城 オンライン自習室 v2 — セットアップ手順

Google Drive 経由で Windows 機に同期される。
Windows 側の `マイドライブ/usami-castle/` を開いて、そこで作業する。

---

## 🔴 最初にやること（他の全部より優先）

古い `app.py` に本物の Discord Webhook URL が直接書かれていた。
その状態で GitHub の Public リポジトリに上げると、世界中の誰でも
そのチャンネルに投稿できてしまう。**まず今使っている鍵を捨てて作り直す。**

1. **Discord の Webhook を作り直す**
   サーバー設定 → 連携サービス → ウェブフック → 古いものを削除 → 新規作成 → URLをコピー

2. **Gemini の APIキーを作り直す**
   Google AI Studio → 古いキーを削除 → 新しいキーを発行

3. **すでに GitHub に上げてしまっている場合**
   リポジトリの `app.py` を開いて、本物のURL・キーが載っていないか確認する。
   載っていたら、上の1・2をやった上でリポジトリを一度 Private にするか、
   古いファイルを削除する。（1・2をやれば古い鍵は無効になるので、実害は止まる）

## セットアップ（5分）

### 1. 秘密情報のファイルを作る

`.streamlit/secrets.toml.example` をコピーして、
同じフォルダに `secrets.toml` という名前で保存する。

中身を、さっき作り直した本物の値に書き換える。

```toml
DISCORD_WEBHOOK_URL = "新しいWebhook URL"
GEMINI_API_KEY = "新しいAPIキー"

[students]
"usami-001" = "テスト生徒"
"usami-002" = "たろう"
```

生徒が増えたら `[students]` に行を足すだけ。
左がその子に渡すID、右が Discord の報告に出る名前。

### 2. ライブラリを入れる

コマンドプロンプトで `usami-castle` フォルダに移動して:

```bash
pip install -r requirements.txt
```

### 3. 起動する

```bash
streamlit run app.py
```

- [ ] `usami-001` でログインできる
- [ ] 入城 → カメラが映る → Discord に入城通知が来る
- [ ] 「てこずったところ」を空のまま送ろうとすると止められる

- [ ] 返信が、褒めるだけでなく**質問を1つ**返してきている

## 🖊 友ちゃんの担当作業

`app.py` の `EXAMPLES = [` を探す。ここだけ編集すればいい。

サンプルを2つ入れてある。同じ形で **8つ足す**。

```python
{
    "done": "生徒が書きそうな『やったこと』",
    "stuck": "生徒が書きそうな『てこずったところ』",
    "reply": "それに対して、僕ならこう返す、という文",
},
```

これが自習室で一番効く作業。
抽象的な指示を10行足すより、実例を1組足す方が効く。

**一番いい実例が採れるタイミング**は、生徒への返信を見て
「いや、僕ならそこはこう言う」と思った瞬間。そのとき1組足す。
ゼロから10個ひねり出すより、この直し方の方が圧倒的に楽で、質も高い。

## 世界公開（Streamlit Community Cloud）

1. GitHub にこのフォルダを上げる（`.gitignore` があるので `secrets.toml` は上がらない）
2. share.streamlit.io でリポジトリを指定してデプロイ
3. **Settings → Secrets** に `secrets.toml` の中身をそのまま貼り付ける

コードに秘密を書いていないので、リポジトリは Public のままで安全。

## 変更履歴（v1 → v2）

| # | 変更 | 理由 |
|---|---|---|
| 1 | 報告に「てこずったところ」を追加（必須） | v1の「単語30個やった」だけでは、どんなAIでも一般論しか返せない。情報が無いところからは何も出てこない |
| 2 | ウサミサンの仕事を「褒める」→「質問を1つ返す」 | 人格の演技はAIの最も苦手な軸、具体的な問いを立てるのは最も得意な軸。外したときのダメージも小さい |
| 3 | 「先生の助手」として名乗る | 本人になりきって中身が薄いと偽物感が出る。受付だと分かっていれば、そこそこの返信でも成立する |
| 4 | 秘密情報を `st.secrets` へ | Public リポジトリに鍵が載るのを防ぐ |
| 5 | 返信後にログアウトしていたのを修正 | v1は返信を生成した直後に `logged_in = False` にしていたため、生徒は画面で返信を読めなかった |
| 6 | モデルを `gemini-2.5-flash` → `gemini-2.5-pro` | flash は安い代わりに弱い。この呼び出し回数なら費用は誤差 |
| 7 | `max_output_tokens` を 400 → 800 | 文が途中で切れる事故の原因。長さはプロンプト側で指示する |
| 8 | 滞在時間の記録を追加 | 保護者レポート（フェーズ4）の土台 |
| 9 | カメラに STUN サーバーを指定 | 一部の回線で映像が繋がらない事故を防ぐ |
| 10 | Discord 送信にタイムアウトと例外処理 | Discord が落ちたとき、自習室ごと止まるのを防ぐ |
